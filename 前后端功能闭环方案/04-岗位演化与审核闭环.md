# 前后端功能闭环方案：岗位演化与审核闭环

## 要实现的功能

保留当前已真实接通的岗位演化能力，并把“审核评测”页改成后端驱动：审核项由后端返回，审核按钮调用后端更新状态。

## 已有能力

现有后端已支持：

- `GET /api/v1/evolution/changes`
- `GET /api/v1/evolution/changes/{changeId}/evidence`
- `GET /api/v1/evolution/evidence/{evidenceId}`
- `GET /api/v1/emerging-positions`
- `GET /api/v1/positions/{positionId}`

这些接口不要大改，只补加载态和错误态。

## 审核接口

### 获取审核项

```http
GET /api/v1/reviews
```

可选参数：

- `status`
- `type`
- `keyword`

返回审核项：

- `id`
- `type`
- `title`
- `description`
- `confidence`
- `sources`
- `createdAt`
- `status`
- `targetId`

### 提交审核决策

```http
POST /api/v1/reviews/{reviewId}/decision
```

请求：

```json
{ "status": "approved", "note": "通过" }
```

## 审核项来源

第一阶段不接数据库，使用进程内状态。

审核项生成：

- 能力变更：由 `compute_evolution_changes()` 生成。
- 新岗位：由 `compute_emerging_positions()` 生成。
- 技能归一：先用后端 demo 数据。

审核状态：

- 用内存字典保存。
- 服务重启后丢失可接受。

## 前端改动

`ReviewPage.tsx`：

- 页面加载调用 `api.getReviews()`。
- 点击通过/驳回调用 `api.decideReview()`。
- 成功后更新当前审核项状态。
- 审核备注 textarea 需要纳入状态。

`EvolutionPage.tsx`：

- 补充 loading/error 状态。
- 后端异常时显示提示，不要静默空白。

## 重要细节

- 审核项要和岗位演化结果产生关联，`targetId` 指向 `changeId` 或 `positionId`。
- 当前阶段不要求审核回写图谱，只要状态能更新。
- 保持现有岗位演化页真实数据链路稳定。

## 验收

```powershell
curl http://127.0.0.1:8000/api/v1/reviews
```

页面：

- `/evolution` 仍能展示真实演化数据。
- `/review` 审核列表来自后端。
- 点击通过/驳回后状态改变。
- 控制台无 `/api/v1/reviews` 404。
