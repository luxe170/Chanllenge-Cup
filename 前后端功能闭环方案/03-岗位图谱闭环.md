# 前后端功能闭环方案：岗位图谱闭环

## 要实现的功能

让“岗位图谱”页的节点、边、摘要和节点详情从后端返回。第一阶段可把现有前端 Mock 图谱迁移到后端；第二阶段再基于 JD 数据生成真实图谱。

## 后端接口

### 图谱数据

```http
GET /api/v1/graph?mode=panorama
GET /api/v1/graph?mode=skill_reverse
```

返回：

- `mode`
- `hierarchy`
- `nodes`
- `edges`
- `summary`
- `updatedAt`
- `graphVersion`
- `truncated`

### 根节点

```http
GET /api/v1/graph/roots?mode=panorama
```

用于“全部岗位簇 / 全部技术栈”下拉。

### 节点详情

```http
GET /api/v1/graph/nodes/{nodeId}
```

返回右侧详情面板所需数据。

### 搜索

```http
GET /api/v1/graph/search?keyword=RAG&mode=panorama
```

返回可聚焦的节点简表。

## 第一阶段实现

后端：

- 新增 `graph_service.py`。
- 把 `mock.ts` 中的 `panoramaNodes`、`panoramaEdges`、`skillReverseNodes`、`skillReverseEdges` 迁移到后端 demo 数据。
- 保证所有 `edges[].source/target` 都能在 `nodes` 中找到。

前端：

- `GraphPage.tsx` 改为调用 `api.getGraph(mode)`。
- 统一 mode：`panorama | skill_reverse`。
- 保留原 3D 展示和右侧详情逻辑。
- 接口失败时短期 fallback 到原 Mock。

## 第二阶段真实化

复用 `evolution_service.py` 中已有的岗位和技能规则，从 `relevant_jobs.jsonl` 生成：

- 岗位簇节点
- 岗位节点
- 技能节点
- `岗位 -> 岗位簇`
- `岗位 -> 技能`

技能权重：

```text
命中该技能的岗位 JD 数 / 该岗位总 JD 数
```

## 重要细节

- 第一阶段可保留 `x/y` 坐标，减少前端改动。
- 第二阶段应由前端负责布局，后端只返回业务图谱。
- 空结果返回 `nodes: []`、`edges: []`，不要 404。
- 图谱接口是展示重点，必须保证稳定。

## 验收

```powershell
curl "http://127.0.0.1:8000/api/v1/graph?mode=panorama"
curl "http://127.0.0.1:8000/api/v1/graph?mode=skill_reverse"
```

页面：

- `/graph` 能渲染 3D 图谱。
- 切换模式会刷新后端数据。
- 点击节点右侧详情能变化。
- 控制台无 `/api/v1/graph` 404。
