# 前后端功能闭环方案：工作台与评测指标闭环

## 要实现的功能

让“全局工作台”和“审核评测页顶部指标”从后端取数，不再直接使用前端 Mock。

## 后端接口

### 工作台摘要

```http
GET /api/v1/dashboard
GET /api/v1/dashboard/summary
```

返回：

- `sourceCount`
- `validCount`
- `emergingCount`
- `changedCount`
- `metrics`

### 评测摘要

```http
GET /api/v1/evaluations/summary
```

返回：

- `metrics`
- `pendingReviewCount`
- `highPriorityReviewCount`
- `testedAt`

## 数据来源

第一阶段建议：

- `validCount`：统计 `data/processed/relevant_jobs.jsonl` 行数。
- `emergingCount`：复用 `compute_emerging_positions()` 的 total。
- `changedCount`：复用 `compute_evolution_changes()` 的 total。
- `metrics`：先用后端 demo 固定值。

## 前端改动

`DashboardPage.tsx`：

- 页面加载时调用 `api.getDashboard()`。
- 失败时 fallback 到原 `dashboardSummary`。

`ReviewPage.tsx`：

- 顶部评测指标调用 `api.getEvaluationSummary()`。
- 审核列表暂由后续审核方案处理。

`api.ts` 新增：

- `getDashboard`
- `getEvaluationSummary`

## 重要细节

- 工作台是最轻量的闭环模块，优先实现。
- 不要为了评测指标引入真实评测集，第一阶段固定值即可。
- 数据文件缺失时后端返回 0 和 demo metrics，不要报 500。

## 验收

```powershell
curl http://127.0.0.1:8000/api/v1/dashboard
curl http://127.0.0.1:8000/api/v1/evaluations/summary
```

页面：

- `/dashboard` 统计卡正常显示。
- `/review` 顶部评测指标正常显示。
- 控制台无 404。
