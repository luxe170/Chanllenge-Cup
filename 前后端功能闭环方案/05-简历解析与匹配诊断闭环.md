# 前后端功能闭环方案：简历解析与匹配诊断闭环

## 要实现的功能

让“简历解析”和“匹配诊断”具备真实接口链路。第一阶段不做真实 LLM 解析，只做任务式 API 和后端 demo 结果。

## 简历接口

### 创建解析任务

```http
POST /api/v1/resume-tasks
Content-Type: multipart/form-data
```

上传字段：

- `file`

返回：

- `taskId`
- `status`
- `progress`

### 查询解析任务

```http
GET /api/v1/resume-tasks/{taskId}
```

返回：

- `taskId`
- `status`
- `progress`
- `error`
- `result`

`result` 包括候选人信息、技能列表、项目经历和技能证据。

### 修正技能

```http
PATCH /api/v1/resume-tasks/{taskId}/skills
```

第一阶段可只接收并返回修正后的技能列表。

## 匹配接口

### 创建匹配报告

```http
POST /api/v1/matches
```

请求：

- `resumeTaskId`
- `positionId`

返回：

- `matchId`
- `overallScore`
- `level`
- `dimensions`
- `strengths`
- `gaps`
- `suggestions`

### 学习路径

```http
GET /api/v1/matches/{matchId}/learning-path
```

返回阶段化学习路径。

## 后端实现

新增：

- `resume_service.py`
- `match_service.py`
- `routers/resume.py`
- `routers/matches.py`

第一阶段：

- 简历任务存在内存字典中。
- 上传后可直接返回 `succeeded` 和 demo 解析结果。
- 匹配报告可先使用 demo 数据。

如果想半真实：

- 岗位要求调用 `compute_position_profile(positionId)`。
- 简历技能用 demo。
- 用技能名称交集计算基础匹配分。

## 前端改动

`ResumePage.tsx`：

- 选择文件后调用 `api.createResumeTask(file)`。
- 再调用 `api.getResumeTask(taskId)`。
- 用后端返回结果渲染技能和经历。

`MatchPage.tsx`：

- 进入页面时调用 `api.createMatch()`。
- 再调用 `api.getLearningPath(matchId)`。
- 用后端返回数据替换页面内固定数组。

## 重要细节

- 上传接口只做闭环，不要求保存文件。
- 第一阶段不要在线调用 LLM。
- 任务式接口要先定好，后续真实解析可以无缝替换。
- 没有 `resumeTaskId` 时，后端可使用 demo resume，保证演示稳定。

## 验收

页面：

- `/resume` 上传文件后显示后端返回的解析结果。
- `/match` 显示后端返回的匹配报告和学习路径。
- 控制台无 resume/matches 相关 404。
