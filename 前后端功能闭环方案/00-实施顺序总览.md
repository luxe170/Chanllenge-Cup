# 前后端功能闭环方案：实施顺序总览

## 目标

把当前“前端完整 demo，后端只支撑岗位演化”的状态，推进到“所有页面都通过后端接口取数”。第一阶段先做功能闭环，数据可以是后端 demo 或半真实计算，不要求一次接入全部真实数据和 LLM。

## 当前状态

已接真实后端：

- 岗位演化：能力变更、新岗位发现、证据链、原始 JD、岗位定义。

仍是前端 Mock：

- 全局工作台
- 岗位图谱
- 简历解析
- 匹配诊断
- 审核评测

## 推荐实现顺序

1. 公共接口底座：补统一响应、router/service 分层、前端 API 方法和错误 fallback。
2. 工作台与评测指标：先把统计卡和评测指标从后端返回。
3. 岗位图谱：先让图谱节点和边由后端返回；初版可迁移现有 Mock。
4. 岗位演化与审核：保留现有岗位演化真实逻辑，把审核台改成后端接口。
5. 简历解析与匹配诊断：先做任务式接口和 demo 结果，不接真实 LLM。
6. 数据处理与 LLM 边界：明确哪些先用规则，哪些后续用离线 LLM 增强。

## 第一阶段完成标准

- 所有页面都请求后端接口。
- 后端缺真实算法的模块先返回 demo 数据。
- 岗位演化继续基于 `data/processed/relevant_jobs.jsonl` 实时计算。
- 前端不因接口失败白屏，可短期保留 Mock fallback。
- `npm run build` 通过。

## 暂不做

第一阶段不接 Neo4j、不接在线 LLM、不做完整简历解析、不做真实评测集计算。
