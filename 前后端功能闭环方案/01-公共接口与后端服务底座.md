# 前后端功能闭环方案：公共接口与后端服务底座

## 要实现的功能

建立统一的后端接口结构，让后续模块可以按同一方式补功能。重点是把路由、业务服务、响应格式和前端 API 调用方式理顺。

## 后端改动

建议新增：

- `backend/app/routers/`
- `backend/app/services/dashboard_service.py`
- `backend/app/services/graph_service.py`
- `backend/app/services/review_service.py`
- `backend/app/services/resume_service.py`
- `backend/app/services/match_service.py`
- `backend/app/demo_data.py`

在 `main.py` 中注册各 router，保留现有岗位演化接口。

统一响应格式：

```json
{ "data": {}, "requestId": "..." }
```

建议提供 `ok(data)` 工具函数，新增接口统一使用。

## 前端改动

扩展 `frontend/src/services/api.ts`：

- 支持 GET/POST/PATCH。
- 支持 query 参数拼接。
- 支持 `FormData` 上传。
- 新增 dashboard、graph、reviews、resume、matches 等方法。

页面改造时先允许 fallback 到 `frontend/src/data/mock.ts`，避免后端没完成时页面白屏。

## 重要细节

- 所有业务接口统一 `/api/v1` 前缀。
- 后端 demo 数据先集中放在 `demo_data.py`，不要继续散在前端。
- 新增类型尽量和 `frontend/src/types/index.ts` 对齐。
- 先不强制所有接口加 `response_model`，但字段名必须稳定。

## 验收

启动后端后，以下接口不能 404：

```powershell
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/api/v1/dashboard
curl "http://127.0.0.1:8000/api/v1/graph?mode=panorama"
curl http://127.0.0.1:8000/api/v1/reviews
```

前端构建通过：

```powershell
cd frontend
npm run build
```
