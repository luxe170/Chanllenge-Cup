# 前端适配与改进方案

本文面向当前 `frontend/` React + TypeScript 项目，目标是从全页面 Mock 演示切换到真实知识图谱后端，同时保留前端的三维布局能力。

## 1. 当前必须改的地方

当前所有页面直接导入 `src/data/mock.ts`，`GraphPage.tsx` 也绕过了已经存在的 `services/api.ts`。因此即使后端上线，页面也不会发出网络请求。

优先修改：

1. 页面只从服务层或查询 Hook 获取数据，禁止直接导入 Mock；
2. `api.ts` 从假延迟函数改为真正的 HTTP 客户端；
3. 增加加载、空结果、错误、重试和后台任务状态；
4. 将 Mock 保留为 Storybook/测试 fixture，不参与生产构建；
5. 使用环境变量配置 API 地址，禁止在组件内硬编码。

建议配置：

```text
VITE_API_BASE_URL=http://localhost:8000/api/v1
VITE_GRAPH_CONTRACT=canonical
```

## 2. 契约选择

后端同时提供两套返回方式：

- `contract=canonical`：推荐长期使用，节点类型明确；
- `contract=frontend_v1`：旧页面的短期兼容方式。

规范类型：

```ts
type GraphNodeType =
  | 'position'
  | 'position_category'
  | 'skill'
  | 'skill_cluster'
  | 'tech_stack'

type GraphRelationship = 'IN_CATEGORY' | 'REQUIRES' | 'BELONGS_TO'
type GraphMode = 'panorama' | 'skill_reverse'
```

当前前端存在两处命名冲突：

- 页面内部使用 `skill`，后端和接口文档使用 `skill_reverse`；
- 当前 `cluster` 同时表示岗位类别和技能簇。

建议一次性切换到规范契约。若团队时间紧，第一轮可以请求 `contract=frontend_v1`，但应建立明确的删除日期。

## 3. 服务层改造

建议目录：

```text
frontend/src/
  services/
    client.ts             # fetch、超时、请求 ID、错误转换
    graph.ts              # 图谱查询
    pipeline.ts           # 构建任务查询
    review.ts             # 审核数据
    evolution.ts          # 演化与证据
  hooks/
    useGraph.ts
    useGraphNode.ts
    usePipelineRun.ts
    useEvolution.ts
  types/
    api.ts
    graph.ts
```

HTTP 客户端至少处理：

- `VITE_API_BASE_URL`；
- `AbortController` 超时和组件卸载取消；
- 非 2xx 响应；
- 后端 `{data, requestId}` 包装；
- 将 `X-Request-Id` 显示在错误详情中，便于联调排查；
- GET 请求的查询参数编码；
- 仅对幂等 GET 做有限次数重试。

不要在浏览器中保存或发送生产 `ADMIN_API_KEY`。当前 API Key 适合 CLI、运维任务或受信代理；如果审核页面面向真实用户，应由团队的登录/BFF 层完成鉴权和权限控制。

## 4. 图谱页改造

### 4.1 数据流

```text
路由和筛选状态
  -> GET /graph/roots
  -> GET /graph
  -> 前端计算三维坐标
  -> 用户选中节点
  -> GET /graph/nodes/{id}
  -> 右侧详情面板
```

需要修改 `GraphPage.tsx`：

- 删除 `panoramaNodes`、`panoramaEdges` 等 Mock 导入；
- 将内部模式 `skill` 改为 `skill_reverse`；
- 模式、根节点、搜索词和焦点节点进入 URL 查询参数，便于分享和刷新恢复；
- 顶部统计直接使用后端 `summary`；
- 更新时间和版本使用 `updatedAt`、`graphVersion`；
- 右侧详情改为按选中 ID 请求，不再用固定数字；
- 搜索框调用 `/graph/search`，防抖约 300ms；
- 下拉框调用 `/graph/roots`；
- `truncated=true` 时显示“当前为子图”提示和继续缩小范围的入口；
- 空图不是错误，应展示筛选建议。

### 4.2 Graph3D 边界

保留当前前端负责坐标、相机、旋转和标签避让的设计。后端不会返回 `x/y/z`。

建议进一步优化：

- 节点数超过阈值时降低球体细分和标签数量；
- 只为选中节点、相邻节点和高权重节点显示 HTML 标签；
- 对节点和边使用实例化渲染，避免每个对象单独创建 Three.js mesh；
- 取消请求后不要把旧结果写回新模式；
- 使用后端稳定 ID 保存选中态，不依赖数组下标；
- 节点新增时平滑重排，避免整个场景跳动。

## 5. 岗位详情与证据

岗位详情页调用：

- `GET /positions/{positionId}`；
- `GET /positions/{positionId}/evidence?skillId=...`。

界面应明确区分：

- 技能本身的属性；
- 该岗位对技能的 `requirementType`、`weight`、`frequency` 和 `confidence`；
- 支撑关系的 JD 数量和时间范围；
- 原始证据句、企业、时间和来源链接。

不要把“必备/加分”放到技能节点上，它属于岗位—技能关系。

## 6. 演化页面

使用：

- `GET /evolution/changes`；
- `GET /evolution/changes/{id}/evidence`；
- `GET /evolution/evidence/{sourceId}`；
- `GET /emerging-positions`。

改进点：

- 变化记录展示前后 `weight/frequency/requirementType`，不要只显示描述文本；
- 证据链按企业和时间排序；
- 原始 JD 使用抽屉或弹窗按需加载；
- 明确标注“算法候选”“待人工确认”“已发布”；
- 新岗位页展示样本数、企业来源数、首次/最近出现时间和候选技能；
- 不要将增长率单独当作新岗位结论。

## 7. 审核页面

后端目前提供岗位候选和低置信度关系审核。前端应支持：

### 新岗位候选

- 查看规范化标题、原始写法、样本数、来源数、时间范围和候选技能；
- 选择“链接已有岗位”并搜索标准岗位；
- 或选择“创建新岗位”，填写标准名称、岗位类别、描述；
- 批准后提示需要重新运行构建任务才能更新正式图谱。

### 低置信度关系

- 查看岗位、技能、权重、频率和证据；
- 批准、拒绝、修正要求类型；
- 展示审核人、审核时间和备注。

生产环境不能由浏览器直接持有管理 API Key。建议接入团队统一登录，或增加服务端 BFF 将用户会话转换为后端受信调用。

## 8. 构建任务页面

新增管理页面或在工作台增加“图谱构建”区域：

- `POST /pipeline-runs` 创建任务；
- `GET /pipeline-runs/{id}` 轮询状态；
- 状态包括 `queued / claimed / running / publishing / completed / failed`；
- 失败任务展示错误摘要，并调用 `/pipeline-runs/{id}/retry`；
- 完成后展示输入数、技能证据数、聚合关系、发布关系、审核数和图谱版本。

轮询建议：运行中 2 秒一次；页面进入后台后降低频率；完成或失败后停止。

## 9. 推荐实施顺序

### 第一阶段：真实图谱联调

1. 建立 HTTP 客户端和规范 TypeScript 类型；
2. 改造图谱页使用 `GET /graph`；
3. 接入 roots、search 和 node detail；
4. 接入岗位详情和证据；
5. 增加加载、空结果和错误状态；
6. 删除生产路径上的 Mock 导入。

### 第二阶段：演化与审核

1. 演化列表和证据链；
2. 新岗位候选；
3. 审核交互；
4. 构建任务状态和失败重试；
5. 图谱版本显示。

### 第三阶段：质量与性能

1. 请求契约测试；
2. 图谱大节点数性能测试；
3. 键盘操作和可访问性；
4. 错误监控和请求 ID；
5. 移除 `frontend_v1` 兼容层。

## 10. 前端验收标准

- 生产代码搜索不到从 `data/mock` 的业务导入；
- 两种图谱模式均由真实接口驱动；
- 刷新页面后筛选和焦点可恢复；
- 所有边的端点均能找到对应节点；
- 300、600、1000 节点下交互有明确性能指标；
- 空图、后端不可用、超时和截断均有可理解提示；
- 任意岗位—技能关系可以进入原始证据；
- 构建任务在 API 或页面重启后仍能继续被 worker 处理；
- 管理密钥不进入前端包、LocalStorage 或浏览器网络配置；
- Mock 只用于测试和组件预览。
