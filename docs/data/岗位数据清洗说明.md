# 岗位数据清洗说明

## 输入与输出

清洗程序以 `data/raw/bytedance_dev_jobs.jsonl` 为输入，不修改 `data/raw` 中的原始数据。

运行：

```bash
python src/processing/clean_job_postings.py
```

输出文件：

| 文件 | 说明 |
|---|---|
| `data/processed/cleaned_job_postings.csv` | 通过校验的清洗后岗位记录 |
| `data/processed/rejected_job_postings.csv` | 被拒绝的记录及拒绝原因 |
| `data/processed/cleaning_report.json` | 清洗数量和质量统计 |

## 清洗规则

1. 统一 Unicode 字符、空白符、换行符和时间格式。
2. 去除职位 URL 中的查询参数和片段。
3. 使用 `bytedance:<position_id>` 生成稳定的 `source_id`。
4. 缺少职位 ID、标题、职责、要求或合法 URL 的记录进入拒绝表。
5. 同一 `source_id` 出现多次时，仅保留字段更完整、正文更长的记录。
6. 标题、职责和要求完全相同但职位 ID 不同的记录不删除。这类记录通常是跨城市或跨时间发布，使用 `duplicate_group_id` 和 `duplicate_content` 标记。
7. 缺少发布时间的记录保留，并使用 `missing_publish_time` 标记。

## 衍生字段

| 字段 | 说明 |
|---|---|
| `source_id` | 原始招聘记录的稳定业务主键 |
| `content_hash` | 标题、职责和要求组成的 SHA-256 内容指纹 |
| `duplicate_group_id` | 内容相同记录的分组编号 |
| `quality_flags` | 使用分号分隔的数据质量标记 |

清洗结果仍然属于岗位发布记录，不是标准化后的 `Position` 节点。岗位名称标准化和岗位聚类在后续流程中完成。
