### 二、知识图谱构建

**输入**：预处理后的结构化岗位数据

**输出**：岗位-技能知识图谱（要构建什么样的图谱？构建知识图谱的方法有很多，采用什么方法？）

**图谱 Schema**：

- 节点：TechStack（技术栈）、SkillCluster（技能簇）、Skill（具体技能）、Position（工作岗位）
- 边：BELONGS_TO（层级归属）、REQUIRES（岗位要求技能，分为必备和加分？）、SIMILAR_TO（岗位相似）、PREREQUISITE（技能前置关系）、IN_INDUSTRY（所属行业）
- 三级层级：Skill → SkillCluster → TechStack，通过 BELONGS_TO 边串联，支撑视图切换

**具体工作内容**：

- 图谱存储与 Schema 设计
- 从岗位数据中抽取实体、属性与关系的抽取策略
- 图谱写入模块：实现增量构建，支持去重和动态更新
- 技能层级（TechStack → SkillCluster → Skill）的初始化：对常见技能做批量分类，后续增量补充

### 三、新一代信息技术岗位全景图谱

**输入**：知识图谱

**输出**：前端可视化界面，支持三级粒度切换

**具体工作内容**：

- 编写三级查询（技术栈视图 / 技能簇视图 / 技能点视图）
- 前端展示：岗位-技能关系图、按技术栈或行业筛选、技能热力图（按频次）、新岗位标注（按首次出现时间）
- 支持交互：点击节点下钻/上卷切换粒度

### 四、人岗匹配度诊断与差 距分析

**输入**：求职者简历（PDF/Word） + 目标岗位名称

**输出**：差距分析报告 + 学习路径建议

**具体工作内容**：
- 简历文本提取（PDF/Word 解析）
- 从简历中抽取技能列表
- 实体链接模块：将简历技能映射到图谱中的 Skill 节点
- 图谱查询：获取目标岗位的必备技能清单
- 差距计算：对比简历技能 vs 岗位技能，输出缺失项和熟练度不足项
- 生成可读差距报告和学习路径建议

- 解决噪音的问题：噪音包括抄袭和通胀现象。（通胀？？可能是指要求的技能比实际用到的要多？）

## PRD：岗位能力动态图谱与人岗匹配系统

### 1. 产品背景

当前新一代信息技术领域岗位变化快，企业招聘 JD 中存在时滞、噪声、抄袭、技能通胀等问题，传统关键词匹配难以准确识别新兴岗位、更新既有岗位能力，也难以对个人简历进行细粒度人岗差距分析。

本系统面向人工智能、大数据、智能系统、物联网等新一代信息技术领域，构建一个基于多源数据、大模型与知识图谱的岗位能力动态演化分析系统。

### 2. 产品目标

构建一套从数据采集、能力抽取、新岗位发现、既有岗位更新、岗位能力图谱构建，到简历解析、人岗匹配和学习路径推荐的闭环系统。

| 目标 | 说明 |
|---|---|
| 新岗位发现 | 自动识别市场中正在兴起的新岗位，并生成岗位定义 |
| 既有岗位更新 | 识别已有岗位能力要求的新增、删除、修改 |
| 能力图谱构建 | 构建技能点级岗位能力知识图谱 |
| 人岗匹配 | 解析简历技能，与目标岗位能力图谱对比 |
| 差距分析 | 输出技能缺失项、匹配度和改进建议 |
| 动态演化 | 支持数据更新、人工优化和图谱持续迭代 |

### 3. 用户角色

| 用户 | 诉求 |
|---|---|
| 求职者/学生 | 了解目标岗位要求，分析自身差距，获得学习路径 |
| 企业 HR/招聘负责人 | 了解岗位能力变化，提高招聘匹配效率 |
| 教师/指导老师 | 查看技术岗位趋势，指导学生能力培养 |
| 系统管理员/专家 | 审核新岗位、修正能力项、维护图谱质量 |
| 评审人员 | 查看系统完整性、创新性、准确率和演示效果 |

### 4. 核心业务流程

```text
多源数据输入
 -> 多源异构数据采集与清洗
 -> 交叉验证融合与能力抽取
 -> 数据与能力可信性判断
 -> 岗位分析提取模块
 -> 新岗位发现与定义 / 既有岗位能力动态更新
 -> 岗位能力图谱动态构建
 <- 人工优化与动态更新
 -> 全景图谱可视化
 -> 简历解析
 -> 目标岗位图谱对比
 -> 人岗匹配诊断与差距分析
 -> 改进建议与学习路径规划
 -> 测试验证与作品交付
```

### 5. 功能模块

| 模块 | 输入 | 输出 |
|---|---|---|
| 多源数据采集与清洗 | 招聘 JD、岗位库、技能库、技术趋势数据 | 清洗后的岗位文本、标准化岗位名、标准化技能词 |
| 交叉验证与能力抽取 | 清洗后文本、多源证据 | 岗位名称、职责、技能项、场景、证据链、置信度 |
| 可信性判断 | 抽取结果、证据链、置信度 | 可信数据进入岗位分析；不可信数据返回清洗/核验 |
| 岗位分析提取 | 可信岗位信息、职责、技能 | 岗位类型、能力集合、职责集合、变化特征 |
| 新岗位发现与定义 | 岗位分析结果、既有岗位库、趋势数据 | 新岗位名称、核心职责、必备技能、加分技能、应用场景 |
| 既有岗位能力更新 | 既有岗位画像、历史能力、最新 JD | 能力新增/删除/修改项、更新说明、数据来源 |
| 人工优化与动态更新 | 待确认岗位、争议能力项、低置信度结果 | 人工确认结果、修正后的岗位定义、修正后的能力项 |
| 岗位能力图谱构建 | 新岗位定义、既有岗位更新、人工修正结果 | 技能点级岗位能力知识图谱 |
| 全景图谱可视化 | 岗位能力图谱 | 按技术栈、岗位级别切换的图谱视图 |
| 简历解析 | PDF/Word 简历、用户技能输入 | 简历技能要素、项目经历、能力标签 |
| 人岗匹配与差距分析 | 简历技能、目标岗位图谱 | 匹配分数、技能缺失项、优势能力、改进建议 |
| 学习路径规划 | 技能差距、目标岗位、技能依赖关系 | 学习路径、优先级、推荐补强方向 |
| 测试验证 | 至少 100 条 JD、测试用例、简历样例 | JD 解析准确率、简历提取准确率、匹配准确率 |

### 6. 核心功能需求

#### 6.1 新岗位发现与定义

系统应从多源数据中识别新兴岗位，判断其是否区别于既有岗位。

输出内容包括：

```text
岗位名称
岗位类型：新兴岗位
核心职责
必备技能
加分技能
典型行业应用场景
发现依据
数据来源
置信度
人工审核状态
```

判断依据包括：

```text
岗位名称新颖度
技能组合差异度
JD 出现频次
近期增长趋势
与既有岗位相似度
多源证据一致性
```

#### 6.2 既有岗位能力动态更新

系统应针对已有岗位识别能力变化。

输出内容包括：

```text
岗位名称
岗位类型：既有岗位
新增能力项
删除能力项
修改能力项
更新说明
数据来源
更新时间
置信度
人工审核状态
```

#### 6.3 岗位能力图谱

图谱需要支持技能点级颗粒度。

建议核心 schema：

```text
Job：岗位
JobProfile：岗位画像
SkillPoint：技能点
TechStack：技术栈
Level：岗位级别
Responsibility：职责
Scenario：应用场景
Evidence：证据来源
ChangeEvent：能力变更事件
LearningPath：学习路径
```

核心关系：

```text
Job -> HAS_PROFILE -> JobProfile
JobProfile -> REQUIRES -> SkillPoint
SkillPoint -> BELONGS_TO -> TechStack
JobProfile -> HAS_LEVEL -> Level
JobProfile -> HAS_RESPONSIBILITY -> Responsibility
JobProfile -> APPLIES_TO -> Scenario
JobProfile -> SUPPORTED_BY -> Evidence
JobProfile -> HAS_CHANGE -> ChangeEvent
SkillPoint -> PREREQUISITE_OF -> SkillPoint
```
