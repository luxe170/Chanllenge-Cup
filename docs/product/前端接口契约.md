# 前端接口契约 V1

## 1. 约定

- API 前缀：`/api/v1`
- 响应格式：`{ "data": ..., "requestId": "..." }`
- 时间统一使用 ISO 8601 格式。
- 图谱接口返回当前视图需要的子图，不一次返回全量图谱。
- 简历解析采用任务式接口，前端轮询任务状态。

## 2. 工作台

### `GET /dashboard/summary`

返回工作台顶部统计卡所需数据：有效岗位样本数量、新兴岗位数量和能力变更数量。

响应字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `validCount` | `number` | 清洗、去重后的有效岗位样本数量 |
| `emergingCount` | `number` | 当前识别出的新兴岗位数量 |
| `changedCount` | `number` | 当前统计周期内发生变化的岗位能力数量 |

## 3. 岗位图谱

### 3.1 图谱数据

### `GET /graph`

返回当前模式需要展示的子图。前端负责三维自动排版，后端不得返回 `x`、`y`、`z` 等坐标。

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `mode` | `panorama \| skill_reverse` | 是 | 图谱视图模式 |
| `rootId` | `string` | 否 | 全景模式传岗位簇 ID；技能反查传技术栈 ID |
| `focusNodeId` | `string` | 否 | 指定首次进入时选中的节点 |
| `keyword` | `string` | 否 | 按岗位簇、技术栈、岗位或技能名称搜索并返回相关子图 |
| `maxNodes` | `number` | 否 | 最大节点数，默认 `300`，上限 `1000` |

模式对应的固定层级：

| `mode` | 层级顺序 |
|---|---|
| `panorama` | 岗位簇 → 岗位 → 技能点 |
| `skill_reverse` | 技术栈 → 技能簇 → 技能点 → 岗位 |

响应结构：

```json
{
  "data": {
    "mode": "panorama",
    "hierarchy": ["cluster", "position", "skill"],
    "nodes": [],
    "edges": [],
    "summary": {
      "positionClusterCount": 3,
      "techStackCount": 0,
      "skillClusterCount": 0,
      "positionCount": 7,
      "skillCount": 10
    },
    "updatedAt": "2026-08-03T10:00:00+08:00",
    "graphVersion": "2026-08-03.1"
  },
  "requestId": "req_xxx"
}
```

#### 节点 `nodes[]`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | `string` | 全局唯一节点 ID |
| `type` | `cluster \| stack \| position \| skill` | 节点类型 |
| `name` | `string` | 标准名称，后端不插入换行符 |
| `trend` | `new \| rising \| stable \| declining` | 可选，仅用于节点状态展示，不参与当前页面筛选 |
| `weight` | `number` | 可选，节点在当前子图中的相对权重，范围 `0～1` |
| `sampleCount` | `number` | 可选，支持该节点的有效岗位样本数 |
| `firstSeen` | `string` | 可选，首次发现日期，格式 `YYYY-MM-DD` |

`cluster` 在 `panorama` 中表示岗位簇，在 `skill_reverse` 中表示技能簇；`stack` 表示技术栈。

节点示例：

```json
{
  "id": "pos_ai_agent_engineer",
  "type": "position",
  "name": "AI Agent 研发工程师",
  "trend": "new",
  "sampleCount": 38,
  "firstSeen": "2025-08-12"
}
```

#### 关系 `edges[]`

| 字段 | 类型 | 说明 |
|---|---|---|
| `source` | `string` | 起点节点 ID |
| `target` | `string` | 终点节点 ID |
| `relationship` | `BELONGS_TO \| REQUIRES` | 关系类型 |
| `requirementType` | `required \| preferred` | 仅 `REQUIRES` 必填，分别表示必备和加分 |
| `weight` | `number` | 可选，岗位对该技能的要求权重，范围 `0～1` |
| `confidence` | `number` | 可选，关系可信度，范围 `0～1` |

关系方向固定为：

- `岗位 --BELONGS_TO--> 岗位簇`
- `技能簇 --BELONGS_TO--> 技术栈`
- `技能点 --BELONGS_TO--> 技能簇`
- `岗位 --REQUIRES--> 技能点`

`requirementType` 属于“岗位—技能”关系，不能放在技能节点上。同一个技能对不同岗位可以分别是 `required` 或 `preferred`。

关系示例：

```json
{
  "source": "pos_ai_agent_engineer",
  "target": "skill_rag",
  "relationship": "REQUIRES",
  "requirementType": "preferred",
  "weight": 0.84,
  "confidence": 0.93
}
```

### 3.2 顶部下拉选项

### `GET /graph/roots`

用于“全部岗位簇/全部技术栈”下拉框。

查询参数：`mode=panorama|skill_reverse`。

```json
{
  "data": [
    { "id": "position_cluster_ai", "name": "人工智能研发岗位簇", "nodeCount": 24 }
  ],
  "requestId": "req_xxx"
}
```

`panorama` 返回岗位簇，`skill_reverse` 返回技术栈。

### 3.3 节点详情

### `GET /graph/nodes/{nodeId}`

返回右侧详情面板数据。公共字段为 `id`、`type`、`name`、`description`、`sampleCount`、`firstSeen` 和 `confidence`。

不同节点补充字段：

| 节点类型 | 补充数据 |
|---|---|
| 岗位簇 | 标准岗位数、有效样本数、直接关联节点 |
| 技术栈 | 技能簇数、技能点数、关联岗位数 |
| 技能簇 | 技能点数、有效样本数、直接关联节点 |
| 岗位 | 必备技能列表、加分技能列表；列表项来自 `REQUIRES` 关系 |
| 技能点 | 技能权重、关联岗位数、相邻岗位；不返回固定要求类型 |

岗位详情中的技能列表项格式：

```json
{
  "skillId": "skill_rag",
  "name": "RAG",
  "requirementType": "preferred",
  "weight": 0.84,
  "confidence": 0.93
}
```

### 3.4 搜索建议

### `GET /graph/search`

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keyword` | `string` | 是 | 最少 2 个字符 |
| `mode` | `panorama \| skill_reverse` | 是 | 当前视图模式 |
| `limit` | `number` | 否 | 默认 `10`，上限 `30` |

返回可作为 `focusNodeId` 的节点简表：`id`、`type`、`name`。

### 3.5 前后端职责边界

- 后端负责节点、关系、层级、权重、可信度和业务统计。
- 前端负责三维坐标、同层自动排版、缩放、旋转、节点选中和标签避让。
- 后端新增节点时只需返回节点及关系，前端自动重新排版。
- 后端必须保证 `edges[].source` 与 `edges[].target` 均存在于本次返回的 `nodes` 中。
- 空结果正常返回 `nodes: []`、`edges: []`，不返回 `404`。
- 图谱过大时后端按 `maxNodes` 截断，并额外返回 `truncated: true`。

### 3.6 完整岗位画像

### `GET /positions/{positionId}`

用于进入岗位完整数据页。返回标准岗位定义、职责、场景、别名和技能要求。技能要求中的 `requirementType`、权重和可信度来自岗位—技能关系，而非技能节点。

## 4. 岗位演化

岗位演化页面仅保留“能力变更记录”和“新岗位发现”两个标签页，以及能力变更的右侧证据链。页面不再请求顶部统计卡或技能趋势图数据。

### 4.1 能力变更记录

### `GET /evolution/changes`

用于“能力变更记录”标签页。

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keyword` | `string` | 否 | 按岗位名称或技能名称搜索 |
| `page` | `number` | 否 | 页码，默认 `1` |
| `pageSize` | `number` | 否 | 每页数量，默认 `20`，上限 `100` |

响应结构：

```json
{
  "data": {
    "items": [
      {
        "id": "change_001",
        "positionId": "pos_ai_agent_engineer",
        "positionName": "AI Agent 研发工程师",
        "skillId": "skill_multi_agent",
        "skillName": "多智能体协作",
        "changeType": "new",
        "before": null,
        "after": {
          "requirementType": "preferred",
          "weight": 0.72
        },
        "evidenceCount": 25,
        "confidence": 0.87,
        "detectedAt": "2026-07-29T10:00:00+08:00"
      }
    ],
    "total": 47,
    "page": 1,
    "pageSize": 20
  },
  "requestId": "req_xxx"
}
```

字段约束：

| 字段 | 类型 | 说明 |
|---|---|---|
| `changeType` | `new \| rising \| declining` | 分别对应新增、上升、下降 |
| `before` | `RequirementSnapshot \| null` | 历史窗口状态；首次新增时为 `null` |
| `after` | `RequirementSnapshot` | 当前窗口状态 |
| `evidenceCount` | `number` | 支持本次变化的有效 JD 数量 |
| `confidence` | `number` | 综合可信度，范围 `0～1` |

`RequirementSnapshot`：

```json
{
  "requirementType": "required",
  "weight": 0.81
}
```

`requirementType` 取值为 `required`（必备）或 `preferred`（加分）。

### 4.2 变化证据链

### `GET /evolution/changes/{changeId}/evidence`

点击能力变更记录后调用，用于右侧“变化证据链”。

```json
{
  "data": {
    "changeId": "change_001",
    "positionId": "pos_ai_agent_engineer",
    "positionName": "AI Agent 研发工程师",
    "skillId": "skill_multi_agent",
    "skillName": "多智能体协作",
    "before": null,
    "after": {
      "requirementType": "preferred",
      "weight": 0.72
    },
    "confidence": 0.87,
    "sourceSupport": {
      "companyCount": 3,
      "jobCount": 25
    },
    "windowContinuity": {
      "continuousWindowCount": 3,
      "passed": true
    },
    "semanticConsistency": 0.94,
    "evidenceIds": ["jd_1001", "jd_1002"]
  },
  "requestId": "req_xxx"
}
```

`evidenceIds` 供“查看原始证据”功能使用，不在本接口中返回完整 JD 正文。

### `GET /evolution/evidence/{evidenceId}`

返回单条原始证据，包括企业名称、岗位名称、采集时间、来源平台、脱敏后的 JD 原文和命中片段。

### 4.3 新岗位发现

### `GET /emerging-positions`

用于“新岗位发现”标签页。

查询参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keyword` | `string` | 否 | 按岗位名称或技能名称搜索 |
| `page` | `number` | 否 | 页码，默认 `1` |
| `pageSize` | `number` | 否 | 每页数量，默认 `20`，上限 `100` |

响应结构：

```json
{
  "data": {
    "items": [
      {
        "id": "emerging_001",
        "positionId": "pos_ai_agent_engineer",
        "name": "AI Agent 研发工程师",
        "description": "聚焦智能体编排、工具调用与工作流研发",
        "growthRate": 1.68,
        "confidence": 0.93,
        "firstSeen": "2025-03-01",
        "sourceCount": 4,
        "sampleCount": 52,
        "skills": [
          { "id": "skill_langchain", "name": "LangChain" },
          { "id": "skill_rag", "name": "RAG" },
          { "id": "skill_multi_agent", "name": "多智能体协作" }
        ]
      }
    ],
    "total": 12,
    "page": 1,
    "pageSize": 20
  },
  "requestId": "req_xxx"
}
```

`growthRate` 使用小数表示，`1.68` 由前端显示为 `+168%`。它表示当前统计窗口相较上一窗口的岗位样本增长率，不等同于新岗位判定结果；是否属于新岗位以 `confidence` 和后端判定规则为准。

### 4.4 前端调用规则

- 页面首次进入时请求 `GET /evolution/changes`，并默认选中第一条记录。
- 默认选中后请求对应的证据链接口。
- 切换到“新岗位发现”时再请求 `GET /emerging-positions`。
- 两个标签页顶部数字分别使用各自接口返回的 `total`。
- 搜索框作用于当前标签页，输入防抖建议为 `300ms`。
- 空列表正常返回 `items: []` 和 `total: 0`。

## 5. 简历与匹配

### `POST /resume-tasks`

使用 `multipart/form-data` 上传 PDF、DOC 或 DOCX，返回 `taskId`。

### `GET /resume-tasks/{taskId}`

返回任务阶段、进度、错误信息和解析结果。解析结果包含基本信息、教育经历、项目经历、技能实体、熟练度、原文证据与可信度。

### `PATCH /resume-tasks/{taskId}/skills`

提交用户对技能抽取结果的新增、删除或修正。

### `POST /matches`

输入 `resumeTaskId` 与 `positionId`，返回总体匹配度、维度得分、优势技能、能力差距、证据引用和岗位适配建议。

### `GET /matches/{matchId}/learning-path`

返回按前置关系和优先级组织的学习阶段、技能、预计耗时、阶段目标和学习任务。

## 6. 人工审核与评测

### `GET /reviews`

查询新岗位、能力变更和技能归一审核项。

### `POST /reviews/{reviewId}/decision`

提交 `approved` 或 `rejected` 决策及审核备注。

### `GET /evaluations/summary`

返回 JD 解析、简历提取和人岗匹配准确率、样本数、目标值及测试时间。

## 7. Schema 补充要求

岗位图谱当前不提供岗位级别、能力趋势和最低可信度筛选。后端可以保留相关业务字段，但不应将其作为 `GET /graph` 的必填查询参数。

三维坐标属于前端展示状态，不写入 Neo4j，也不通过图谱接口返回。

学习路径、简历、匹配报告、完整证据和审核记录按现有 Schema 设计保存在图谱外，由业务数据库和聚合 API 提供。
